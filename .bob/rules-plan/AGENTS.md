# Project Architecture Rules (Non-Obvious Only)

- **Provider routing**: Codex reaches ICA through `[model_providers.ica]` with `wire_api = "responses"` and `env_key = "ICA_API_KEY"`. Do not change `wire_api` to a completions format.
- **Catalog coupling**: `ica-models.json` is referenced by `config.toml` through `model_catalog_json`. Every model slug in `config.toml` (e.g. `gpt-advantage-assist`, `gpt-5.6-sol`) must exist in the catalog's `"models"` array.
- **Dual credential path**: The CLI reads `ICA_API_KEY` from the session environment and `~/.codex/.env`. VS Code and GUI apps read the Windows User env var or the profile `.env`. Both must be set for multi-client use.
- **Dry-run and backups**: Every script operation needs a non-mutating preview (`-DryRun` / `--dry-run`). File modifications offer timestamped backups first. Directory creation must be idempotent (`mkdir -p` / `New-Item -Force`).
- **codex-security is a separate provider path**: It does not inherit `config.toml`. ICA is wired through `~/.codex/codex-security.yaml`, selected by `CODEX_SECURITY_PROJECT_CONFIG`. It is opt-in, and the Windows sandbox startup failure is outside this toolkit's authentication fix.
- **Uninstaller**: `uninstall-codex-ica.{ps1,sh}` confirm once (default No), then prompt per item: daemons, each npm package, `~/.codex` (owner-only backup first), each User env var, the `~/codex-ica-test` workspace, and on macOS/Linux the npm prefix and `~/.zshrc` PATH line. Prerequisites (Git, gh, Node.js, Python via winget/brew) are offered last with default No and are never approved by `-Yes` / `--yes` / `-NonInteractive`. `-KeepConfig` / `-KeepApiKey` (`--keep-config` / `--keep-api-key`) opt out of parts of that. Keep the prerequisite list in sync with the setup scripts.
